### Q1. 출퇴근 시각은 어느 테이블에 저장되나요?

**배경:**
API 명세서에는 아래처럼 날짜별 출퇴근 시각이 필요합니다.
```json
"attendance": {
  "records": [
    { "date": "2025-06-02", "inTime": "09:05", "outTime": "18:10" }
  ]
}
```
그런데 ERD를 분석했더니 **일반 출퇴근 기록 전용 테이블이 없었습니다.**
`HR_LEAVE`(연차), `HR_OVRTM_WOR`(초과근무)는 있는데, 매일 출퇴근 시각을 기록하는 테이블이 보이지 않았어요.

**확인 필요:**
- 출퇴근 기록이 저장되는 테이블 이름이 무엇인지
- 혹시 ERD에서 빠진 테이블이 있는지

---

### Q2. 지각 판단은 누가 하나요?

**배경:**
API 명세서에는 `"isLate": true/false` 필드가 있습니다.

**두 가지 가능성:**
- **Waple이 계산해서 보내주는 경우** → 우리는 그냥 받기만 하면 됨
- **우리가 계산해야 하는 경우** → `HR_WORKTP.WORK_BGNG_TM`(정규 출근 시간)과 실제 출근 시각을 비교하는 로직 필요

어느 쪽인지에 따라 우리 코드 구조가 달라집니다.

---

### Q3. 업무일지 keywords는 누가 추출하나요?

**배경:**
API 명세서 Request에 아래 필드가 있습니다.
```json
"workLog": {
  "entries": [
    { "date": "2025-06-02", "keywords": ["회의", "보고서", "기획"] }
  ]
}
```
`keywords` 필드가 이미 들어오는 건지, 아니면 우리가 `HR_TASK_LOG.MEMO` 컬럼에서 NLP로 직접 추출해야 하는 건지 불명확합니다.

**확인 필요:**
- Waple이 미리 추출해서 보내주는지
- 우리가 MEMO 텍스트에서 직접 추출해야 하는지

---

### Q4. DB에 직접 접근할 수 있나요, 아니면 Waple API만 사용하나요?

**배경:**
현재 알고 있는 것: Waple이 POST로 데이터를 보내줌.

**확인 필요:**
- 우리가 직접 DB 쿼리를 날릴 수 있는지 (DB 접속 정보 제공 여부)
- Waple API를 통해서만 데이터를 받아야 하는지
- 추가로 필요한 데이터가 있을 때 요청할 수 있는 창구가 있는지

### Q5. 직원 HR 데이터를 OpenAI 같은 외부 API로 전송해도 되나요?

**배경:**
GPT-4o-mini를 사용하려면 직원 이름, 근태, 업무일지 내용 같은 개인정보가 OpenAI 서버로 전송됩니다.
회사 보안 정책에 따라 이게 허용되지 않을 수 있어요.

**결과에 따른 방향:**
| 답변 | 우리가 할 것 |
|------|------------|
| 외부 전송 가능 | GPT-4o-mini 사용 → 바로 시작 가능 |
| 외부 전송 불가 | EXAONE 3.5 로컬 실행 → GPU 서버 필요 |

---

### Q6. GPU 서버 지원이 가능한가요?

**배경:**
EXAONE 3.5 (7.8B 모델)를 로컬에서 실행하려면 GPU가 필요합니다.
우리 팀 노트북으로는 돌리기 어렵고, 유시스 측 서버 지원이 있어야 합니다.

**확인 필요:**
- GPU 서버 제공 가능 여부
- 가능하다면 스펙과 접속 방법

## 🟡 Category 3. 점수 설계 기준 (팀 합의 필요)

### Q7. 상태코드 변환 기준을 어떻게 정할까요?

**배경:**
점수를 `0010(양호) / 0020(주의) / 0030(위험)`으로 변환하는 기준을 우리가 직접 설계해야 합니다.

**제안안:**
```
80점 이상 → 0010 (양호)
60~79점   → 0020 (주의)
60점 미만 → 0030 (위험)
```
이 기준으로 갈지, 아니면 다른 기준을 쓸지 팀 합의 필요.

---

### Q8. 4개 점수의 종합점수 가중치를 어떻게 할까요?

**배경:**
관리자 리포트의 `totalScore`는 4개 점수(목표/업무일지/근태/연차)를 합산한 값입니다.
단순 평균을 쓸지, 가중 평균을 쓸지 결정이 필요합니다.

**제안안:**
```
목표점수      30%
업무일지점수  25%
근태점수      30%
연차점수      15%
```
또는 단순 평균(25% × 4)으로 갈 수도 있음. 팀 합의 필요.

---

### Q9. 레이더차트 5개 축 점수를 어떤 데이터로 계산할까요?

**배경:**
`coreScore` 5개 축(실행력/안정성/성장력/효율성/영향력)의 점수를 우리가 직접 설계해야 합니다.
각 축이 어떤 DB 데이터와 연결되는지 아직 정의가 안 돼 있습니다.

**예시 제안:**
| 축 | 연결 데이터 |
|----|-----------|
| 실행력 | 목표 완료율 (`HR_AIM.CRNT_ACHV_RATE`) |
| 안정성 | 근태 점수 (지각/결근 기반) |
| 성장력 | 목표 진행률 추이 |
| 효율성 | 업무일지 작성률 |
| 영향력 | 팀 기여 목표 수 |

이 연결 방식이 맞는지 팀 논의 필요.

**배경:**

### Q11. 우리 AI 서버의 Base URL은 어떻게 할까요?

**배경:**
API 명세서에 `Base URL은 여러분이 결정`이라고 명시되어 있습니다.
개발 단계에서는 `http://localhost:8000`으로 시작하지만, Waple과 실제 연동할 때는 외부 접근 가능한 URL이 필요합니다.

**확인 필요:**
- 개발 중 테스트할 때 Waple이 우리 서버에 어떻게 접근하는지
- ngrok 같은 터널링 도구를 쓸지, 유시스 측 서버에 배포할지
